모두가 AI에게 지시해서 결과를 낸다. 그래도 각 역할이 맡는 판단은 다르고, 서로 대신할 수 없다. "AI는 손을 대신해도 판단은 대신하지 못한다."

역할결정권직접 고쳐서 바로 올리는 것직접 손대지 않는 것
PO 무엇을 만들지 문구, 버튼 위치 같은 작은 수정 큰 기능 — 스펙 문서로 써서 개발자에게 넘긴다
디자이너 어떻게 보일지 화면(UI) 코드 — 디자인 툴에서 끝내지 않고 직접 고쳐서 머지한다 데이터를 다루는 백엔드
개발자 무너지지 않게 (구조) 백엔드, 아키텍처 —

개발자의 추가 역할

  • ADR 작성을 이끈다.
  • 팀에서 남의 작업을 가장 많이 읽고 리스크를 짚는다.

PO의 원칙

작은 건 손으로, 큰 건 문서로. 코드를 쓰지 않더라도 데이터가 어디서 와서 어디로 가는지는 이해한다. 그래야 "어렵다"는 말을 판단 없이 그대로 받아들이지 않게 된다.

경계가 애매할 때

대화로 정하고, 정한 결과는 이 문서에 반영한다. 같은 질문이 두 번 나오지 않게 하기 위해서다.
