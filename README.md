# ai-native-starter

3~5명 팀이 **모두 AI에게 지시해서 일하는** 방식으로 프로젝트를 시작할 때 쓰는 템플릿입니다.
메이커 에반의 영상 「3명이서 회사 하나를 굴리는 법」([youtu.be/cojswCxZgsg](https://youtu.be/cojswCxZgsg))에서 소개한 방식을 파일로 옮겼습니다.

> 오늘 하나만 가져간다면: **진실은 한 군데에만.**

이 템플릿은 시작할 틀일 뿐입니다. 도구가 일하는 방식을 만들어 주지는 않습니다. 방식은 아래의 첫 한 달 실천으로 만듭니다.

## 들어 있는 것

| 파일 | 역할 |
|---|---|
| `docs/working-agreement.html` | **일하는 규칙의 유일한 원본.** 무엇을 어디에 쓰나, 초안과 논의, 하루 흐름, 리뷰 규칙 |
| `docs/roles.html` | 역할과 경계: 최소 세 자리의 결정권, 직접 고치는 범위, 다음에 더할 자리 |
| `docs/adr/` | 결정 기록. 결정 / 이유 / 버린 것만 쓴다. `0001`은 이 방식 자체를 채택한 결정 |
| `docs/specs/` | 큰 기능용 스펙 템플릿 ("작은 건 손으로, 큰 건 문서로") |
| `docs/index.html` | 문서 허브. 아침에 여기서 시작한다 |
| `AGENTS.md` / `CLAUDE.md` | AI에게 `docs/`부터 읽게 하는 안내. 규칙 자체는 `docs/`에만 있다 |
| `.github/pull_request_template.md` | 리뷰 체크리스트: 문서와 다른 점만 본다 |
| `scripts/new-adr.py` | 번호를 매겨 새 ADR 초안을 만들고 index에 링크를 추가한다 |
| `scripts/morning.sh` | 최근 바뀐 문서와 커밋을 보여준다 (아침 10분 읽기용) |

## 쓰는 법

1. 이 템플릿으로 새 레포를 만듭니다 (**Use this template** 또는 `gh repo create <조직>/<레포> --template agiletalk/ai-native-starter --private --clone`).
   - 이미 레포가 있으면 `docs/`, `scripts/`, `AGENTS.md`, `CLAUDE.md`, `.github/`를 복사해 넣습니다.
   - 레포가 여러 개인 프로젝트라면 문서가 사는 레포를 하나로 정하고, 나머지 레포의 `AGENTS.md`는 그 레포의 `docs/`를 가리키게 합니다.
2. `docs/roles.html`을 팀 구성에 맞게 고칩니다.
3. `docs/adr/0001-*.html`의 작성일과 작성자를 채웁니다. 팀이 Markdown을 원하면 0002로 번복하면 됩니다.
4. 비개발자도 문서를 열 수 있게 합니다. 레포를 받아 두고 `docs/index.html`을 브라우저로 열거나, GitHub Pages처럼 웹으로 띄워 둡니다.

## 첫 한 달: 이 세 가지만

한꺼번에 다 바꾸려 하면 거의 실패합니다.

1. **결정 하나를 문서로 남긴다.** 최근에 팀이 내린 가장 중요한 결정 하나를 세 줄로 씁니다.
   ```bash
   scripts/new-adr.py payment-provider "결제사는 OO로 한다"
   ```
2. **비개발자 한 명이 아주 작은 것을 직접 고쳐서 올린다.** 오타 하나면 충분합니다. 결과보다 "나도 만질 수 있다"는 경험이 중요합니다.
3. **중복 문서 하나를 지운다.** 같은 내용이 두 곳에 있는 걸 찾아 하나를 지우고 링크로 바꿉니다. 만드는 것보다 지우는 게 어렵습니다.

그 뒤의 하루 흐름과 리뷰 방식은 `docs/working-agreement.html`을 따릅니다.

## 알고 시작해야 할 비용

영상에서 직접 밝힌 단점입니다.

- **문서 작성에 시간이 많이 든다.** 업무 시간의 약 3분의 1이 문서 작업입니다.
- **AI에게 지시하는 실력은 사람마다 차이가 크다.** 경험이 적을수록 무엇을 요청해야 할지 몰라 어려워합니다. 영상 속 팀도 아직 답을 찾지 못했다고 합니다.
- **소수 팀은 여유가 없다.** 한 명이 빠지면 그 주가 그냥 지나가고, 휴가를 겹쳐 쓸 수 없습니다.
- **큰 팀에서는 검증되지 않았다.** 3명에서 확인한 방식이고, 30명에서는 아직 모릅니다.
