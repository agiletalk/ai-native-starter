# ai-native-starter

2~5명 팀이 **모두 AI에게 지시해서 일하는** 방식으로 프로젝트를 시작할 때 쓰는 템플릿입니다.
메이커 에반의 영상 「3명이서 회사 하나를 굴리는 법」([youtu.be/cojswCxZgsg](https://youtu.be/cojswCxZgsg))에서 소개한 방식을 파일로 옮겼습니다.

> 오늘 하나만 가져간다면: **진실은 한 군데에만.**

## 들어 있는 것

| 파일 | 역할 |
|---|---|
| `AGENTS.md` / `CLAUDE.md` | AI 작업 규칙. 문서를 먼저 읽고, 진실은 한 곳에만 두고, 결론은 문서에 남긴다 |
| `docs/index.html` | 문서 허브. 아침에 여기서 시작한다 |
| `docs/roles.html` | 역할과 경계: PO·디자이너·개발자가 각각 어떤 결정권을 갖고 무엇을 직접 고치는지 |
| `docs/adr/` | 결정 기록. 결정 / 이유 / 버린 것만 쓴다. `0001`은 이 방식 자체를 채택한 결정 |
| `docs/specs/` | 큰 기능용 스펙 템플릿 ("작은 건 손으로, 큰 건 문서로") |
| `.github/pull_request_template.md` | 리뷰 체크리스트: 문서와 다른 점만 본다 |
| `scripts/new-adr.py` | 번호를 매겨 새 ADR 초안을 만들고 index에 링크를 추가한다 |
| `scripts/morning.sh` | 최근 바뀐 문서와 커밋을 보여준다 (아침 10분 읽기용) |

## 쓰는 법

1. 이 폴더를 복사해 새 레포로 만듭니다. 이미 레포가 있으면 `docs/`, `scripts/`, `AGENTS.md`, `CLAUDE.md`, `.github/`를 복사해 넣습니다.
2. `docs/roles.html`을 팀 구성에 맞게 고칩니다.
3. `docs/adr/0001-*.html`의 작성일과 작성자를 채웁니다. 팀이 Markdown을 원하면 0002로 번복하면 됩니다.

## 시작하는 순서: 한 달 동안 이 세 가지만

한꺼번에 다 바꾸려 하면 거의 실패합니다.

1. **결정 하나를 문서로 남긴다.** 최근에 팀이 내린 가장 중요한 결정 하나를 세 줄로 씁니다.
   ```bash
   scripts/new-adr.py payment-provider "결제사는 OO로 한다"
   ```
2. **비개발자 한 명이 아주 작은 것을 직접 고쳐서 올린다.** 오타 하나면 충분합니다. 결과보다 "나도 만질 수 있다"는 경험이 중요합니다.
3. **중복 문서 하나를 지운다.** 같은 내용이 두 곳에 있는 걸 찾아 하나를 지우고 링크로 바꿉니다. 만드는 것보다 지우는 게 어렵습니다.

**도구 구매부터 시작하지 마세요.** 프로세스가 먼저고 도구는 나중입니다.

## 하루 흐름

| 시간 | 하는 일 |
|---|---|
| 아침 | 회의 없이 `scripts/morning.sh` (월요일은 `scripts/morning.sh 3`)와 문서를 10분 읽는다 |
| 낮 | 각자 작업한다. 문서에 없는 일이 생길 때만 대화하고, 대화의 결론은 문서에 넣는다 |
| 오후 | PR 리뷰. 좋고 나쁨이 아니라 **문서와 다른지만** 본다 |
| 퇴근 전 | 오늘 바꾼 것을 올린다. 그게 다음 날 아침에 읽을 거리가 된다 |
| 주 1회 | 큰 그림을 보는 회의 |

## 초안과 논의는 PR로

문서도 확정되기 전에 먼저 올립니다.

- ADR이나 스펙 초안은 `status: draft`로 PR을 엽니다.
- "이 부분은 반대예요, 이유는 이거예요" 같은 논의는 PR 리뷰 댓글로 합니다.
- 합의가 되면 status를 `accepted`로 바꾸고 머지합니다.
- 결정을 번복할 때는 기존 ADR을 고치지 않습니다. 새 ADR을 만들고 기존 문서를 `superseded`로 표시합니다.

## 알고 시작해야 할 비용

영상에서 직접 밝힌 단점입니다.

- **문서 작성에 시간이 많이 든다.** 업무 시간의 약 3분의 1이 문서 작업입니다.
- **AI에게 지시하는 실력은 사람마다 차이가 크다.** 경험이 적은 사람일수록 무엇을 요청해야 할지 몰라 어려워합니다.
- **소수 팀은 여유가 없다.** 한 명이 빠지면 그 주가 그냥 지나갑니다. 큰 팀에서 통하는지는 검증되지 않았습니다.
